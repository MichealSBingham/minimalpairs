## Product contract

The default is audio-only, cross-word ABX discrimination. A and B represent the contrasting categories; X is a different word. The learner matches the target sound or feature. Words, IPA and meanings stay absent from the trial and accessible labels unless hints are explicitly enabled. See [OPERATING_RULES.md](OPERATING_RULES.md).

The production session length is 12. Reference A/B use the same voice profile; X randomly uses a different available profile. Target category, correct A/B position and reference voice use independent draws; there are no fixed answer/category/voice quotas. Reference-pair coverage is shuffled, and the full available voice pool is eligible. Each of A/B/X must finish successful playback before answering. Text-hint use remains marked for the entire session, and assisted results are excluded from audio-only accuracy.

## Run and verify

From `rescue/app`, use `npm ci`, `npm run dev`, `npm test`, and `npm run build`. The Node dependencies are pinned by the lockfile. The build validates the eight-language content and produces static files in `app/dist`.

Copy `app/.env.example` to `app/.env` and supply the Firebase web configuration. These public identifiers are distinct from server credentials. Keep service-account keys, payment keys and all customer data out of the app and its public assets. For this preview, `SITE_URL=https://minimalpairs.web.app` and `PUBLIC_SITE_INDEXABLE=false`.

The local development server is at http://localhost:4321. When changing dependencies, restart it if cached development modules fail to load. The deployed preview does not use development hot reload.

Content checks live in `content/audit_curriculum.py`. Audio generation, repair and engineering coverage checks are documented in [audio/README.md](audio/README.md). Audio is generated locally once and cached as MP3 files; generation code and model weights are not deployed.

## Deploy and rollback

From `rescue/app`, run `npm run deploy:preview`. It builds into a fresh temporary directory outside the synced workspace, verifies preview noindex metadata, and deploys only that artifact using the existing Hosting configuration. Do not deploy the synced `dist` directory: background sync can introduce duplicate conflict copies after a build. The script prints the retained artifact path for inspection. Deploy rule changes separately with `--only firestore:rules` after the emulator tests described in the migration README. The hosting configuration serves only `dist`; it must never point to the workspace or migration directory.

Before a subsequent deployment, inspect the current Hosting release and retain its version ID in the release record. Firebase Hosting's release history supports rolling back to an earlier release; a hosting rollback does not undo Firestore grants. Keep migration changes grant-only and review any entitlement correction separately. The initial rescue release and the compact-mobile update are recorded in `releases.json`; the original custom-domain product remains separate.

Before custom-domain cutover, verify the preview's core flow, pronunciation quality, paid coverage and remaining old paths. Change canonical/site settings and indexability together only for the intended public production domain. Twenty-eight configured redirects cover twenty-six genuinely corresponding old contrast routes, the old Chinese language path and login. Twenty-six old French/English contrast topics still lack curriculum replacements; three further English topics have text but only device-voice preview audio. Unrelated redirects do not count as restoration.
